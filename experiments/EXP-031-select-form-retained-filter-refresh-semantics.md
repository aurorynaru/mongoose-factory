## Objective

On the existing live Web Client only: characterize whether the Select Form dialog retains and APPLIES an exact Name filter after an ordinary dialog Cancel and one reopen. Sequence per cycle-task briefs:
1. Positive control (known-present `FX_ComponentRecoveryLab02`): with Filter By=Name, Case Sensitive unchecked, Starts With unchecked — set the exact filter, ordinarily Cancel, reopen Select Form exactly once, inspect retained text/settings BEFORE further input and inspect the newly settled rendered row result.
2. Only if the positive-control retained-filter result passes: absence probe `FX_SelectFormFilterProbe01` (never created by this experiment; database absence never presumed from the name or repo history): set exact filter, Cancel, reopen once, inspect retained text/settings and visible case-insensitive matches.
3. Final ordinary Cancel to dismiss the test dialog without another reopen; record final state.

Observed mechanics already accepted (corroboration for planning only): filter-text fill alone does NOT re-render rows from an already-open dialog (EXP-030 T2, EXP-028, EXP-029); settled filtered views come from Open-with-filter-at-open (EXP-027-R2/EXP-028 AC-1 paths). Whether Cancel RETAINS filter text/settings across reopen was never characterized — that is this experiment's question.
