## Property classes with a domain (dropdown and validation without a validator)
These are created in the IdoPropertyClasses runtime Form (data-layer.md). Set:
- Domain IDO (e.g. `FX_UMs`);
- Domain Property (`FX_UM`);
- Domain List Properties (`FX_Description`).

Effects (EXP-050, 051, 072):
- Properties using the class are generated by the Multi-View wizard as **ComboBoxes** that list `code  description` in key order.
- Free typing is allowed. Save rejects values outside the domain: "<value> is not a valid <caption>". The draft stays editable.
- Class Default Value reaches the runtime (e.g. `0.00`), not the SQL column.

## Choosing between them
- **Simple lookup + validation on an IDO property:** property-class domain. This is the least work and applies wherever the class is used.
- **Validation or list on a specific component, shared across forms:** validator + component class.
- **Drill-down to the master record:** property-class extension (right-click Details).
- **Required:** tick Required on the IDO property or in the wizard grid (Primary Key implies Required).

All of these are **tenant-wide** global objects, so names with the build prefix (`FX_` by default) only, unless approved. Validators and component classes are saved with a Designer Save ("Global object(s) were saved.").
