# EXP-033-R4: five bounded replay tasks

Model: sonnet; effort: high. Brief remains unreviewed until the operator approves it.

## Chrome launch options for R4

R4 must start Chrome with the new launch options. After R3 has finished,
run `chrome stop` and `chrome start` before R4's operator preconditions:

```powershell
.\claude-harness.ps1 chrome stop
.\claude-harness.ps1 chrome start
```

This restart must not happen while R3 is running. Do not execute these commands
during R3; its open Select Form and browser state must be preserved.

## Operator preconditions

- Owned Chrome is visible and logged in to the Web Client.
- Chrome window visible and not covered by other windows for the whole run
  (do not minimize it); same window size for R3 and R4.
- Mongoose configuration selected (the OK button on the Infor configuration screen
  clicked) and the Web Client is loaded, showing the normal Web Client page,
  not a sign-in or configuration screen.
- Select Form is closed.
- There are no unsaved Designer changes.
- The old harness and OpenCode are not running.
- Use the same starting state for R3 and R4; record it if it differs.

Instructions below are only the coordinator text after the old run's marker,
with experiment IDs/paths and OpenCode worker wording adapted. Source run:
`tools/learning-harness/data/runs/R-20261007-220054-xlTM`.
No old preamble or harness-added boundaries are included. Commands run from
`tools/claude-harness`; the wrapper invokes `claude-harness worker task`.

Use a fresh session for T1 and retain its UUID for T2–T5. Keep this PowerShell
session open. Review the complete result/evidence before manually proceeding.
Never run all five blocks unattended or repeat an interrupted instruction.
Exit 3 (`completed_with_denials`) means review the permissionDenials, warning,
full report and evidence, then continue manually only if the next task is permitted.
A completed task can still report an experiment blocker.

**Review blockers resolved:** Select Form state is checked against T1, recovery
counts continue from the experiment record, and an in-page dialog may remain
open when the current task explicitly requires it. Browser-native dialogs and
unsaved-change prompts must always be absent at task end. Never discard unsaved
work; report a blocker instead. Both briefs still require operator review.
