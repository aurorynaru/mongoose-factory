# 1\. Project and workflow

The project is an autonomous **Infor Mongoose factory** being built in C:\\AI\\mongoose-factory. Its long-term goal is to take a natural-language request, optionally with reference images, and reliably build Mongoose Forms/portal-related artifacts using browser automation and a growing set of verified recipes.

There are three roles:

-   **Coordinator (ChatGPT):** decides the next bounded experiment step, reviews worker evidence, decides whether specialist consultation is needed, and controls knowledge promotion from candidate → observed → replay-verified.
-   **OpenCode worker:** operates the actual Mongoose browser through Playwright MCP, writes/updates experiment records, recipes, and evidence files, and must follow the current experiment scope exactly.
-   **Infor Mongoose specialist GPT:** provides Mongoose-domain guidance when a genuinely new concept or unexplained product behavior appears. Its advice is candidate guidance until the browser environment proves it.

The preferred learning pattern is:

```text
specialist guidance if needed
→ controlled EXP-N browser experiment
→ write observed recipe/procedure if successful
→ fresh OpenCode session
→ EXP-N-R2 clean replay
→ promote recipe to verified only if replay succeeds
```

A replay stopped because one of its own required acceptance conditions cannot be satisfied is **blocked**, not evidence that the underlying procedure failed.

The harness/controller automates this coordination. Future coordinator replies must respect the harness action protocol and experiment boundaries supplied by the controller.

# 3\. Decisions and rules established so far

Permanent factory knowledge must be evidence-based:

```text
candidate guidance
→ observed
→ replay-verified
```

A recipe is only verified after a clean replay in a fresh OpenCode conversation reproduces its required semantic postconditions.

Core rules:

-   Modify only factory-owned FX\_ artifacts.
-   Never alter unrelated/non-FX\_ artifacts.
-   Never weaken security or expose credentials.
-   Keep experiments narrowly scoped to one new capability.
-   Read current state before retrying; never blindly replay a mutation after interruption.
-   Record failures, blockers and corrections, not just successes.
-   Evidence should prove state transitions, not every click.
-   A runtime screenshot proves only that a visual state rendered at that moment.
-   An independent Designer reopen is a practical UI-level persistence test, not direct durable-storage proof.
-   A newly opened Designer tab is not automatically a complete cache boundary. Mongoose documentation supports the concern that closed Forms/global objects can remain cached until explicitly unloaded.
-   Explicitly distinguish editing permission from editing scope.
-   Identify the exact Form version by **Form name + ScopeType + ScopeName**.
-   Treat specialist/documentation guidance as candidate evidence for exact **2026.09.08** behavior until the browser environment proves it.
-   Do not generalize recipes beyond the environment, property/component types and workflow actually replayed.
-   Save semantics must be learned experimentally.
-   EXP-005 shows ordinary Designer Save can persist at least a **literal Form-level Caption** through its tested reopen path. This does not establish identical behavior for other metadata classes.
-   After editing Form metadata, compare the saved value with the same Form version after the experiment's required cache/reopen boundary.
-   Do not invent undocumented APIs, direct DB changes, or metadata hacks to force an experiment through.
-   In Select Form, explicitly select the intended row rather than assuming Enter will activate the filtered row.
-   If an experiment defines a prerequisite before an action, obey that prerequisite even when the underlying product would permit the action. A harness restriction is not a Mongoose product requirement.
-   EXP-005-R2 must not be treated as completed replay verification: its required explicit unload was never invoked and final reopen/comparison was not performed.
-   Do not change **Unload IDO Metadata With Forms** merely to satisfy a replay unless a separately approved scope explicitly permits that mutation.
-   Repeated Ext IDs and internal component structures are diagnostic observations, not durable recipe dependencies.
-   Form/global-object cache and IDO metadata cache are distinct concepts, but Mongoose can intentionally clear them together when **Unload IDO Metadata With Forms** is enabled.
-   IDO metadata does not inherently need clearing to test Form scope/version persistence; incidental IDO clearing may nevertheless occur as part of a documented coupled unload.

Current naming conventions:

```text
Forms:       FX_<Purpose>
Components:  FX_<SemanticPurpose><MongooseType>
Variables:   FX_<Purpose>Var   (candidate from EXP-004; no verified variable recipe)
```

# 5\. Negative findings / blocked topics and why

**EXP-004 — Form Variable Fundamentals is blocked.**

Correct Form-variable UI:

```text
Web Designer
→ Details
→ Variables
```

Edit → Variable opens the **Global Objects** editor and is not the Form-variable creation path.

FX\_TestValueVar could be created with:

```text
Global = False
Persistent = False
Value = Seed-A
```

Its definition then failed to survive:

-   ordinary Form Save: **2/2 failures**
-   Regenerate Form: **1/1 failure**
-   total: **3/3 failures**

No variable recipe exists.

This is notably inconsistent with documented Mongoose behavior: Web Designer supports creating/modifying Form variables; variable edits are Form changes; and Regenerate Form is documented as saving the Form, closing it and reopening it.

The evidence therefore demonstrates anomalous behavior relative to the documented save model, but does **not** establish the root cause. Possibilities remain:

-   2026.09.08 product defect,
-   configuration issue,
-   scope/version interaction,
-   unobserved prerequisite,
-   other environment-specific behavior.

Persistent=False controls persistence/lifetime of the variable's **value**. It does not imply that the Form-variable definition should disappear after the Form definition is saved.

Do not work around EXP-004 using bindings, scripts, undocumented APIs, DB edits, Global=True, Persistent=True, or manual metadata manipulation.

**EXP-005-R2 is blocked by experimental isolation criteria, not by a Mongoose unload restriction and not by an observed Caption persistence failure.**

No evidence from R2 shows that the saved Caption failed. Final verification simply never occurred.

# 7\. Additional rules (from the Mongoose specialist reviews, 2026-10-01/02)

1.  **Replay-verified ≠ documented/supported.** Reproducible here does not automatically mean Infor-supported.
2.  Internal Web Designer traffic, Ext IDs, payloads, event names and local JS structures are diagnostic evidence, not supported APIs.
3.  Recipes state semantic postconditions, not internal protocols.
4.  When evaluating scope/version state, identify the exact target by **Form/object name + scope type + scope name** and use an appropriate documented cache boundary.
5.  Form/global-object cache and IDO metadata cache are distinct, but Mongoose provides a documented coupled clearing mechanism when **Unload IDO Metadata With Forms** is enabled.
6.  IDO metadata does not inherently need clearing for a Form scope/version test; however, incidental or intentional IDO clearing during the same unload is valid product behavior when that preference is enabled.
7.  New Forms and customizations of existing Forms both participate in scope/versioning but have different FormSync/upgrade implications.
8.  FX\_ naming is a factory convention, not a Mongoose standard.
9.  Specialist documentation is candidate evidence for exact **2026.09.08** behavior until experimentally confirmed.
10.  Successful persistence inside one experiment is not replay verification.
11.  A new Designer tab is not automatically a cache-independent session; documented Mongoose behavior supports the possibility that closed Forms/global objects remain cached.
12.  Literal Caption persistence and localized Caption design are separate capabilities.
13.  A replay blocked by its own prerequisite remains **blocked**. Do not bypass or silently reinterpret its acceptance criteria.
14.  Distinguish **“the harness prohibits this in the current experiment”** from **“Mongoose prohibits this.”**
15.  Never state that IDO metadata definitely remained loaded during EXP-005-R2. Only **no explicit cache-unload command was invoked** is proven; automatic behavior on Form closure in 2026.09.08 remains unverified.
16.  For future Caption replay, explicitly decide whether incidental IDO-metadata clearing is permitted before execution begins.
